# Troubleshooting

Symptom-indexed. Find the row, apply the fix, follow the path only when you need the mechanism.
**Almost no mechanism is stated in full here** — each row names the file that owns it.
Not here: how a feature works or what it costs (`docs/features/`, `docs/internals/`), what was
measured or refuted (`docs/HISTORY.md`), running a harness (`docs/VALIDATION.md`), rebasing onto a
newer engine (`docs/PORTING.md`), node defaults and the CI/spelling rules (`CLAUDE.md`).

## Raytraced shadows: temporal artifacts

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| A shadow **ghosts or smears** behind a moving object. Worst on a camera-attached view model; strafing worse than turning | The variance clamp is the only thing rejecting a stale tap when a shadow slides across a receiver that did **not** move: that receiver reprojects exactly, so the depth test passes and nothing else rejects it | Lower `denoiser/history_clamp_sigma` (default `2.0`), then `samples_per_light` (2 before 4). Survivor: `cast_shadow = Off` on the view model, or `light_size = 0`. Tuned values and their price: `docs/features/rt-shadows.md` |
| A shadow is **noisy in wide penumbrae** | One traced ray per light per frame at the default; the a-trous reach follows the measured penumbra width | Raise `samples_per_light` (linear cost, every sample traced) or `denoiser/spatial_passes`. `docs/features/rt-shadows.md` |
| A **contact** shadow reads noisy and stays noisy however the filter is widened | At the default `denoiser/min_filter_pixels = 1.0` a penumbra narrower than a pixel is filtered in no a-trous pass at all, so the temporal pass's raw output reaches the screen | Raise `min_filter_pixels` — it only goes up and buys a fringe on every contact edge in the same move (ladder: `docs/features/rt-shadows.md`), or raise `samples_per_light` instead |
| A **muzzle flash or blinking light never converges**, and resets its neighbors' shadows at the same pixel | Denoiser history is keyed on the whole set of light indices and compared for exact equality (`rt_shadow_temporal.glsl:162`), so a changed set is rejected outright | Give the flash `light_size = 0`; turn it off with `visible = false`, never by fading `light_energy`. Full rule: `docs/features/rt-shadows.md` |
| A light faded out **still costs rays** and can still hold a mask channel | The per-pixel ranking floors energy so a zero-energy light does not silently lose its shadow; `distance_fade` holds a slot too | `visible = false`, or free the light (`shadow_opacity <= 0.001` also releases it). `docs/features/rt-shadows.md` |
| Shadows go **stale for a frame or two** after walking around a corner | The denoiser's history textures are cleared on the frame they are created and never again, so any frame `RTShadows::render` returns early leaves them to be reprojected as last frame's | None needed — the depth test, the clamp and `lag_response` heal it in a frame or two. Understood, not a new bug. `docs/internals/rt-shadows.md` |

## Raytraced shadows: a caster is wrong or missing

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| An **imported** mesh casts no raytraced shadow; log repeats `Parameter "vertex_buffer" is null.` once per surface per frame | `blas_create` resolves a vertex buffer through `vertex_buffer_owner` alone (`rendering_device.cpp:323`), so a `storage_buffer_create` RID fails the lookup — and compressed (16-bit) positions, an imported mesh's default, dequantize into such a buffer | Fixed; the symptom identifies the class. Any buffer handed to `blas_create` must come from `vertex_buffer_create`, with device address, AS build input and `BUFFER_CREATION_AS_STORAGE_BIT`. `docs/PORTING.md` stages 0-1; why no rig caught it: `docs/VALIDATION.md` |
| Static casters work, **skinned ones fail**, and restarting does not help (the error blames meshes uploaded before the setting was on — a decoy) | A skinned caster's structure is built from the per-instance buffer the deform pass wrote, not the rest-pose buffer, so that second call site needs the same creation bits — and both buffers of the motion-vector pair do | `docs/PORTING.md`, stage 1 |
| A **billboard, `Sprite3D`, `Label3D`, `fixed_size`/`grow` or custom `vertex()`** casts its shadow in the wrong place | The structure holds the mesh's **stored** vertices at the **authored** transform, so no vertex shader is visible to it. Skinning and blend shapes are the exception: a compute pre-pass writes what it reads | No setting corrects it. `cast_shadow = Off`, or give it real geometry. `shadow_map_enabled` does **not** help — the opaque pass reads the mask whether or not a map was rendered. `docs/features/rt-shadows.md` |
| A **leaf card casts the shadow of its whole quad** | Rays are traced with `gl_RayFlagsOpaqueEXT`, so an alpha-scissor cutout is never evaluated. (Alpha-*blended* and screen-reading materials cast nothing, as under shadow maps) | Real geometry, or `cast_shadow = Off` and let the contact shadow cover it. `shadow_map_enabled` does not help, as above. `docs/features/rt-shadows.md`, `docs/features/screen-space-shadows.md` |
| **`GPUParticles3D` casts no shadow** | A caster must be `INSTANCE_MESH` or `INSTANCE_MULTIMESH`. `CSGShape3D`, `CPUParticles3D` and `GridMap` qualify; `GPUParticles3D` does not, at all | `CPUParticles3D`, or the screen space contact shadow — opaque `GPUParticles3D` is in that pass's caster set and it is the only shadow those particles can have. `docs/features/screen-space-shadows.md` |
| A mesh **updated in place keeps its old shadow** | The structure is cached on `(mesh RID, surface index)` and only *skinned* surfaces carry a version check, so `surface_update_vertex_region()` and `ImmediateMesh` rewrites cast what was first built | Replace the surface outright — `clear_surfaces()` and re-add, what `PrimitiveMesh` does on any property change; that allocates a new buffer and is correct. `docs/features/rt-shadows.md` |
| Shadows **vanish in a dense scene** with nothing in the log | Two ceilings of 65,536, and the one a real scene hits first is silent: the gather stops at 65,536 caster *instances* and warns once; the structure update then stops at 65,536 TLAS entries, one per *surface*, and just breaks out | Reduce surfaces within the lights' reach, or `cast_shadow = Off`. Watch `GODOT_RT_DEBUG=1`'s `update:` line for the TLAS entry count. `docs/internals/rt-shadows.md` |
| **`shadow_caster_mask` does not exclude a caster** (classic: a view model on a high layer), or a mask of `0` makes **everything** cast | 32-bit masks fold to a ray query's 8-bit instance mask by OR-ing the four bytes (`RTShadows::fold_layer_mask`, `effects/rt_shadows.h:77`), so layers 9-32 alias onto 1-8 and a fold of zero is promoted to `0xFF`. Masking is GPU-side only, so an excluded caster is still gathered and built | `GeometryInstance3D.cast_shadow = Off` is the only removal. `docs/features/rt-shadows.md` |

## Raytraced shadows: a receiver is wrong

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| **Volumetric fog under a lamp casts no shafts**; **subsurface transmittance** stops responding to what is in front of the light; **alpha-blended geometry receives no shadow** | All three read a shadow map and find none. (Alpha blending cannot read the mask, which holds one answer per pixel, belonging to the opaque surface behind the glass.) A raytraced `DirectionalLight3D` traces its own ray per froxel and its fog shafts do work | `Light3D.shadow_map_enabled` on that light — these are the only three it buys back. It does **not** buy back the screen space contact shadow for an alpha-blended surface: no map to fall through to. `docs/features/rt-shadows.md` |
| A light overlapping several others renders **fully unshadowed**, with no shadow-map fallback | At most four raytraced lights are shadowed per pixel (the mask is one RGBA8 texel), and at most 128 per 8x8 tile dropped before the ranking. Two open defects fire it early: a spot's cone falloff is ignored in the per-pixel top four, and the sun can lose its channel at grazing incidence | Reduce genuine overlap of shadow-casting lights; `shadow_map_enabled` does not help. Ceilings: `docs/features/rt-shadows.md`; both defects with line cites in its Known gaps |
| **`shadow_opacity` is ignored** under `render_mode vertex_lighting` | The second directional loop, the single place the fade is applied, is compiled out on that path | Open, deliberate — upstream Godot does the same on its cascade path. `docs/internals/rt-shadows.md` |
| The **first frame** with both volumetric fog and a raytraced sun stalls | Two shader variants compile there, the price of not compiling them for projects that never need them | Expected, not a fault. `docs/internals/rt-shadows.md` |

## Raytraced shadows: settings that do not behave as expected

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| `shadow_blur`, atlas size and quadrants, soft-shadow filter quality, `shadow_reverse_cull_face` **do nothing**; `cast_shadow = ON` behaves as `DOUBLE_SIDED` | No shadow map is rendered for a raytraced light, and the mask is per-scenario where `shadow_reverse_cull_face` is per-light, so triangle facing is never culled | Softness is `light_size` / `light_angular_distance`; noise is `samples_per_light` and `denoiser/*`. Full inert list: `docs/features/rt-shadows.md` |
| A `DirectionalLight3D`'s **cascade count and the directional atlas size changed by themselves** | With raytraced directional shadows available, `directional_shadow_mode` is overridden to 2 splits and the shared atlas capped at 1024 — for **every** directional light, because the atlas is shared | `directional/demoted_shadow_mode = Keep Authored`, `demoted_shadow_size = 0`. `docs/features/rt-shadows.md` |
| A new light casts **soft shadows**, the sky draws a **sun disk**, or **lightmap bakes got slower** | This fork's node defaults differ from vanilla and are unconditional, in every renderer | Set `light_size` / `light_angular_distance` back to `0.0`. Defaults table and all four non-shadow consequences: `CLAUDE.md` |
| Turning on `raytraced_shadows/enabled` in the inspector **does nothing until a restart** | `MeshStorage::mesh_add_surface` fixes a vertex buffer's creation bits at upload time, so a mesh loaded while it was off has nothing to build a structure from | Restart. Every other `raytraced_shadows/*` setting is live next frame; the three `directional/*` ones are live but snapshotted once per frame. `docs/features/rt-shadows.md` |
| Shadows are **noisy under an orthographic camera** and the spatial filter appears off | Penumbra width is converted to pixels with a perspective formula that collapses toward zero, so the denoiser sees no penumbra. Separately the directional gather ignores `directional_shadow_max_distance` and sizes the caster volume from `Camera3D.far` (default `4000`) | Open, unfixed; an isometric or 2.5D project feels both. `docs/features/rt-shadows.md`, Known gaps |
| Penumbrae toward the **edges of a wide frame** are filtered too sharply | Penumbra width uses radial distance where `focal_pixels` is a per-view-depth scale (`rt_shadow_trace.glsl:676`); the error is `1/cos(theta)` off axis, so edge penumbrae read 15-30% narrow. Worst on the ultrawide target, worse with a wide FOV | Open, unfixed; the fix is free, `view_depth` is already in a register two lines above. `docs/features/rt-shadows.md` |

## The frame is black, or a pass silently does nothing

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| The **whole scene is black**, lamps light nothing, and turning the denoiser off cures it — or a pass silently stops running after an edit, with only console errors | A C++ push constant struct mismatching its GLSL block, **trailing padding included**: `compute_list_set_push_constant` rejects the call and the dispatch then fails its own check, so the temporal pass never ran and its target held the zero it was cleared to — a mask of zero is every raytraced light fully occluded everywhere | Match the sizes exactly; `glslangValidator -V <shader> -q` prints the block's reflected size (its exact end, not rounded to sixteen). Nine pairings, registry above the assertions in `effects/rt_shadows.h`: `docs/internals/rt-shadows.md`, `docs/PORTING.md`. Both checks are under `DEBUG_ENABLED`, so **only an editor build ever catches this** — `CLAUDE.md` |
| A mask-writing pass fails and the result is the **worst** picture rather than a degraded one | A texture is created cleared to zero, a zero shadow mask reads as fully occluded, and the forward shader samples it unconditionally with nothing to say the value is stale | The pass reports whether it wrote the mask and the caller lights it when it did not; any new early return must preserve that. Same asymmetry in the occlusion buffer, where the safe value is white; the denoiser's history buffers are deliberately exempt (losing those degrades to noise, not to nothing). `docs/PORTING.md`, `docs/internals/rt-shadows.md` |

## Ambient occlusion

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| Occlusion looks **crushed and speckled** | Suspect the transfer before the estimator: the shipped strength curve is a **ratio**, so occlusion approaches black without reaching it, where the earlier subtractive form put part of an interior on exactly zero inside the gather | Put a flawless traced reference through the same curve and see whether the artifact survives — that one measurement settled it. `docs/HISTORY.md`, `docs/VALIDATION.md` |
| **`ssao_intensity = 0` does not disable occlusion, it inverts it** | The strength curve at `gtao_gather.glsl:438-439` divides by `open + (1 - open) * intensity`; at zero the `max(..., 0.0001)` floor takes over and a fully occluded pixel comes out black. Zero is reachable from the inspector | Open defect. Use `Environment.ssao_enabled = false` to turn occlusion off. `docs/internals/ambient-occlusion.md` |
| `ssao_detail`, `ssao_horizon`, `ssao_sharpness`, `quality`, `adaptive_target` or `blur_passes` **do nothing** | Legacy-estimator only; the inspector hides the first three once ground truth is selected | Tune under `rendering/environment/ssao/ground_truth/`. Which stock settings do reach it: `docs/features/ambient-occlusion.md` |
| Occlusion is **wrong under an orthographic camera**, and worse with distance | Three perspective assumptions, no fallback and no warning | Use the legacy estimator on an orthographic viewport until this is fixed. `docs/features/ambient-occlusion.md`; the three code sites in `docs/internals/ambient-occlusion.md` |
| Occlusion **silently reverts to legacy** | Forward+ and single view only — a stereo or XR viewport falls back without saying so, the occlusion buffer being a layer per eye with no notion of a second one | Expected. `docs/features/ambient-occlusion.md` |
| Occlusion is **too weak**, or does not reach into a real interior | `ground_truth/screen_radius` defaults to `0.1`, a fraction of screen **height**, sized for a test scene | Raise `screen_radius` first (a real interior wanted about `0.25` `[game]`). The denoise sizes itself from the radius, so a large value costs taps, not grain. `docs/features/ambient-occlusion.md` |
| Occlusion is wrong on **foliage and slats**, or too bright in contact on **thick** shapes | `ground_truth/thickness` (`0.3`) sets how far behind a sample its back face sits; it is the one genuine tradeoff | Raise toward `1.0` for thick solid shapes, lower for foliage, railings and slats. `docs/features/ambient-occlusion.md` |
| Occlusion **stair-steps at silhouettes** under half resolution | Half resolution never evaluated a pixel near the edge, and no filter invents a sample that was not taken — widening the reconstruction was measured and refused | `ground_truth/shading_rate = Checkerboard` (the default) reconstructs from four neighbors one pixel away. `docs/features/ambient-occlusion.md`, `docs/HISTORY.md` |
| GTAO is **too slow on weak hardware** | Cost is essentially linear in shading rate, with a small fixed share | `ground_truth/shading_rate` is the first knob, read **only** when `rendering/environment/ssao/half_size` is on; `Quarter Resolution` is the cheaper rung. Per-rate milliseconds and the 780M capture that says occlusion is not where to start there: `docs/features/ambient-occlusion.md` |
| **Memory grows** after switching an `Environment` from legacy occlusion to ground truth | The reverse direction clears `RB_SCOPE_GTAO` explicitly (`render_forward_clustered.cpp:2060-2063`); nothing frees the legacy deinterleaved arrays, which cannot use `clear_context` because GTAO's own `RB_FINAL` lives in that scope. Roughly **25 MB per viewport**, stranded in exactly the A/B comparison the class reference invites | Open defect. `docs/internals/ambient-occlusion.md` |

## Screen space contact shadow

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| The contact shadow **reads too faint** | Bend average the march into four buckets, so a pixel needs four samples' worth of agreement before it is fully shadowed — and samples are one pixel apart, so a blade narrower than that is a one-sample occluder | `screen_space_shadows/hardness`, not `surface_thickness`: `0.0` is Bend's behavior exactly, the default `1.0` blends toward the minimum of the same buckets and matches the trace. Hardness sets how dark, thickness how wide, independently; there is no third darkness knob (`contrast` and `strength` are now constants at 4.0 and 1.0). Measured ratios: `docs/HISTORY.md`; settings: `docs/features/screen-space-shadows.md` |
| The contact shadow **covers less area** than a trace of the same geometry | It shadows only from occluders on screen and in front, and shadow length is bounded in **pixels** by the quality tier, not in world units | Not tunable, and `hardness` does not recover area. Add a few hundred low-poly clump proxies at `SHADOWS_ONLY`: they cast a real raytraced shadow while drawing nothing. `docs/features/screen-space-shadows.md` |
| The pass **does nothing at all** | One of: multiview, a reflection probe render, or an **orthographic** camera (first and last warn once — an orthographic projection gives the direction vector a clip `w` of exactly zero and the march takes its direction from that sign); or the light is not the one picked, the mask having one channel and no per-light property. Forward+ only | Expected in all of those. `docs/features/screen-space-shadows.md` |
| **The sun goes out entirely** | A light is marked with `DirectionalLightData::sss_strength` but no mask was written for it, so the shader's lookup reads past the 4x4 fallback texture | Mark a light **only** when a mask is genuinely written for it. `docs/internals/screen-space-shadows.md` |
| `debug_view = Wave Index` **does not fan out** from the sun's screen position | The light's projected coordinate is wrong, and nothing else is worth tuning until it is right. Two deviations from Bend's HLSL fail silently if a port drops them: the clip Y negation, and a signed cast before the wave offset | `docs/PORTING.md`, stage 19. `Edge Mask` is the view for tuning `bilinear_threshold` |
| **Genuine shadows thin at foliage silhouettes** | `ignore_edge_pixels` is on; it helps only where large flat surfaces at grazing angles produce spurious edges along themselves | Leave `ignore_edge_pixels` off for foliage — that is the geometry this feature serves. `docs/features/screen-space-shadows.md` |
| A **hitch on first sight of new geometry** after enabling `restrict_casters` | It switches the depth pre-pass to a variant writing an extra `R8_UNORM` target, and the pipeline pre-warm has no bit for that pass mode, so every material compiles its pre-pass pipeline the first time it is drawn | A first-sight hitch, not a per-frame cost. One of the reasons the setting ships off: `docs/features/screen-space-shadows.md` |
| **`restrict_casters` warns and declines**, leaving every surface casting | One of three: MSAA on (the caster flag's resolve is unwritten — it has to follow the depth's own `best_index` sample), a visible **VoxelGI** (its depth pass variant has priority and nothing writes the caster mask), or `raytraced_shadows/directional/enabled` off (the structure then holds only geometry near raytraced lamps) | Expected. MSAA is deliberately off in this project (`CLAUDE.md`), so that case does not arise here. `docs/features/screen-space-shadows.md` |
| **Alpha-scissor foliage loses its cut-out contact shadow** when `restrict_casters` is on | It is in the acceleration structure, so the restriction takes it out of the screen space caster set, leaving only the whole-quad raytraced shadow | Author that foliage with `cast_shadow = Off` as well. `docs/features/screen-space-shadows.md` |
| The contact shadow looks **shorter with DLSS on** | The march length is fixed in samples and therefore in **internal** pixels | Raise `quality`; there is no world-space knob. Not a bug, it is the upscaler's tradeoff — which fork quantities are in internal pixels: `docs/internals/dlss.md` |

## DLSS and Streamline

### DLSS reports itself unavailable

Check in this order, before reading any message. Full ladder and the startup lines:
`docs/features/dlss.md`.

1. The project is on the **D3D12** rendering driver — the common case, because the editor writes
   `rendering/rendering_device/driver.windows = "d3d12"` into every project it creates, and
   Streamline is loaded from the Vulkan context driver.
2. `rendering/streamline/enabled` is off, or was changed without a **restart** — it replaces the
   process's Vulkan entry-point loader, so it cannot be live.
3. Only the `sl.*.dll` files were copied. Each DLSS feature needs two: the Streamline plugin **and**
   the NGX model (`nvngx_dlss.dll`, `nvngx_dlssg.dll`), which sit apart in the SDK tree.
4. The interposer is unsigned or not signed by NVIDIA — a self-built Streamline is refused.
5. **Every DLSS feature unavailable while Reflex is available** is NGX declining to initialize for
   want of an identity, because Reflex runs through NVAPI instead. Check
   `rendering/streamline/project_id` (or the built-in GUID fallback) before the files.

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| The viewport goes **mostly black under DLSS** but is fine under FSR 2 | A Streamline resource tag landed on something that is not a texture of its own — a swizzled view and a slice both inherit the parent's `VkImage`. FSR 2 is unaffected because it never goes through Streamline's tagging | Turn `rendering/streamline/reactive_mask` back off. **Anything tagged for Streamline must be a texture of its own**; do not re-attempt the view. `docs/internals/dlss.md`, `docs/HISTORY.md` |
| With the reactive mask on, transparency goes **noisy or flickering** rather than sharper | The hint is too strong. Its scale is a fixed `1.0` at the call site, with no setting behind it | Turn the mask off; changing the strength means changing that call site. `docs/features/dlss.md` |
| With the reactive mask on, **no difference either way** | The tag is not reaching DLSS | Read `sl.log` — it says more about this than the engine's own output. `docs/features/dlss.md` |
| **Edges crawl and never resolve** even with the camera still | Godot clears the velocity buffer to `(-1, -1)` as a sentinel; FSR 2 decodes it in its own patched shader, DLSS reads it literally and sees a full screen of motion everywhere the motion pass did not draw | DLSS takes a camera-motion pre-fill of that buffer (`MotionVectorsStore`, no longer MetalFX-only); if this appears, that pre-fill is what broke. `docs/internals/dlss.md` |
| **Ghosting or smearing under camera motion** / ghosting that survives a **still** camera / the image is **stable but soft** or shimmers at native scale | One convention each, and each fails visibly and differently: motion vector sign and `mvecScale`; the `clipToPrevClip` transpose (Godot stores columns and multiplies `M * v`, Streamline stores rows and multiplies `v * M`, and the two cancel); the jitter sign | All three were **confirmed clean on hardware** (RTX 5090, 3440x1440, 3D scale 0.67), so treat these as the attribution ladder for a configuration not yet tried, not as open questions. **A ghosting raytraced shadow is not a DLSS problem** — that denoiser accumulates in both AA configurations, so `denoiser/*` is the knob. `docs/internals/dlss.md`, `docs/features/rt-shadows.md` |
| **World-space label text or a billboard ghosts** under DLSS | A billboard's previous-frame position must be oriented with the **previous** camera; the `memcpy` seeding the previous-frame UBO had left `main_cam_inv_view_matrix` holding the current one, so a billboard reported almost no motion however fast the camera turned | Fixed at `RenderSceneDataRD::update_ubo` (`render_scene_data_rd.cpp:295`), written after the hardware run and not re-tested since. Alpha-blended surfaces also ghost worse under DLSS than FSR 2 unless the reactive mask is on. `docs/internals/dlss.md`, `docs/PORTING.md` |
| An **editor popup renders blank**; `Couldn't create Vulkan swapchain (VkResult error -3)` repeats at frame rate | That code is `VK_ERROR_INITIALIZATION_FAILED`, arriving from a declined before-hook: `sl.dlss_g` is the one plugin hooking `vkCreateSwapchainKHR`, and the interposer returns the hook's error without ever calling the driver. Every editor context menu is an OS window with its own swapchain. Each retry also pays a full `_flush_and_stall_for_all_frames()` | `kFeatureDLSS_G` is left out of `slInit`'s `featuresToLoad` in the editor; super resolution registers no hooks and is unaffected. A game presenting more than one window is still unhandled. `docs/internals/dlss.md` |
| **Frame generation refuses** | One of five: in the editor (the plugin is not loaded there), without motion vectors (so a temporal upscaler or TAA must run), in stereo, on a viewport no window presents, or on a reflection probe render. It refuses through a status bitfield read back each frame and warned once in words; common ones are Reflex not running and the output resolution being too low | Pair it with DLSS or FSR 2 scaling and run it from a game exported against the `windows-template` artifact. Fixed 2x only — dynamic multi-frame generation is D3D12-only in this SDK. `docs/features/dlss.md` |
| A **moving interface element smears** across generated frames | Frame generation is given a hudless color copy but **not UI alpha**: Godot draws canvas straight onto the same render target as the 3D image and has no separate interface target to hand over | None today. The largest known gap, not a bug in the hudless copy. `docs/features/dlss.md` |
| Frame generation **tears, and V-Sync has no effect** | Streamline cannot pace generated frames against vertical sync on Vulkan — that path is D3D12-only | Force V-Sync from the driver control panel. `docs/features/dlss.md` |
| A DLSS request **silently became FSR 2** | The fallback rule in `renderer_viewport.cpp` substitutes FSR 2 wherever DLSS cannot run | **View -> View Information** reports resolutions, scale and preset from `viewport_get_internal_size` and `viewport_get_effective_scaling_3d_mode` — what the renderer did, not what it was asked. `docs/features/dlss.md` |
| The **reported preset is not the one running** | Which model is running **cannot be read back**: `sl::DLSSState` carries only a VRAM estimate, NGX preset parameters are write-only hints, and `sl.dlss`'s debug HUD prints the quality mode, not the preset — the plugin does not know it either. On `Default` the overlay reports the preset the SDK header documents for the mode, labeled as such | NVIDIA's on-screen indicator is authoritative: registry switch `HKLM\SOFTWARE\NVIDIA Corporation\Global\NGXCore\ShowDlssIndicator`, flipped by the SDK's `scripts/ngx_driver_onscreenindicator.reg`. The overlay reads it and defers to the letter on screen. `docs/features/dlss.md` |
| A **mip or tiling defect appears only with DLSS on** | DLSS is the only feature making the render size arbitrary, so it exposes a latent size-alignment assumption — one mip bound in the GTAO depth prefilter admitted a texel past the end of a row | Check a new pass against an **awkward** size, not the native one (`CLAUDE.md`). Defect mechanism: `docs/internals/ambient-occlusion.md`; which fork quantities scale with internal size: `docs/internals/dlss.md` |
| Switching a viewport **away from DLSS at runtime leaks** | `super_resolution_release` appears only in the destructor and `configure()` rebuilds the same object, so the resources leak until the render buffers are destroyed | Open defect. `docs/features/dlss.md` |
| Streamline's **own side of a refusal** is nowhere in the engine's output | Streamline logs warnings and errors to `sl.log` in the user data directory — the only place its own reasoning is recorded | Read `sl.log` before forming a theory. `rendering/streamline/verbose_logging` raises its log level but only after `slInit` succeeds, so it diagnoses a feature that loaded and misbehaved, never one that never loaded. `docs/features/dlss.md` |

## Validation runs and instrumentation

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| A validation run **hangs until the timeout** | A GDScript parse error: Godot opens a window, fails to load the scene and sits there. Cost ten minutes once | Both `run.sh` scripts parse-check headlessly first. Do not write a new harness script. `docs/VALIDATION.md` |
| A validation run **takes itself down** partway through | `pkill -f` cleaning up Xvfb matches the running script's own command line. Happened twice | Kill Xvfb by PID from a `trap`, as the scripts do. `docs/VALIDATION.md` |
| A run **stops reproducing its published numbers** | A rig inherited its quality tier or capture resolution from the shared `project.godot`; the tier bounds the march in pixels and sets area directly, the resolution sets how many pixels wide a blade is | Each rig pins its own tier, resolution and geometry. `SHADOW_RES` and `SHADOW_QUALITY` are for deliberately re-deriving, never for reproducing. `docs/VALIDATION.md` |
| Every **"vs trace" ratio reads pessimistic** | The numbers were scored off sRGB PNG values, and gamma compresses the dark end | Decode to linear before differencing anything; both harnesses already do. The decode and the episode behind it: `docs/VALIDATION.md` |
| `./run.sh opacity`'s shadow-map control reads **something other than `0.500`** | That control renders a path this fork does not touch, which applies `shadow_opacity` exactly once, so at 0.5 it must read exactly `0.500`. It once read `0.336` | Fix the measurement before believing anything else it says. `docs/VALIDATION.md` |
| `OpTypeRayQueryKHR is not supported yet.` at startup under lavapipe | The line comes from the Mesa stack, not the engine, and does not stop the trace | Ignore it; lavapipe does run the raytraced path. The `GODOT_RT_DEBUG` line that settles it: `docs/VALIDATION.md` |
| A two-capture **GTAO cost solve returns a negative fixed cost** | The wrong formula pair for the shading rate — `half_size` on shades a checkerboard, half the pixels, by default | Use the pair matching the rate, and discard the first frame after toggling `half_size` (`gather_size` changes and the buffers are reallocated inside the mark). Both formulas: `docs/VALIDATION.md` |
| A **`restrict_casters` A/B changes the frame by a single pixel** | Every committed rig is grass on an empty ground plane, and a flat plane cannot occlude itself from a 38 degree sun, so there is no redundant casting to remove | Correct, and it tells you nothing. A rig that could settle it needs real props at `cast_shadow = On` among the grass. `docs/VALIDATION.md`, `docs/features/screen-space-shadows.md` |
| **`GODOT_RT_DEBUG=1` prints nothing** | It is an environment variable read once at startup and cached, not a project setting, so a desktop shortcut or the project manager will not carry it | Set it in the launching shell (below). Output goes through `print_line`, so a terminal reads better than the Output panel — the editor's own 3D viewport traces shadows too and its lines interleave with the running project's. Line meanings: `docs/internals/rt-shadows.md` |
| The editor profiler attributes **far more time to the RT path** than `RT_DEBUG cpu` reports | Godot's visual profiler shows the time between one timestamp and the **next**, so every row is named for the work that follows it. `Update RT Acceleration Structures` runs from the caster gather all the way to `Render 3D Scene` and is a strict superset of gather plus build — in a fully raytraced scene it never passes a `> Render Light3D` mark at all, because a light with no shadow map to render is skipped before that mark exists. The same rule makes `Cull DirectionalLight3D, Split N` misleading for the **last** cascade only, whose interval continues through the entire main scene cull | Read `RT_DEBUG cpu` for CPU cost and the Visual Profiler's `Raytraced Shadows` and `Process GTAO` rows for GPU. No `GODOT_RT_DEBUG` figure is GPU time. `docs/VALIDATION.md`, `docs/internals/rt-shadows.md` |

Setting the debug flag, per shell:

```
$env:GODOT_RT_DEBUG = "1"          # PowerShell, then launch the editor from that shell
set GODOT_RT_DEBUG=1               # cmd
GODOT_RT_DEBUG=1 ./godot ...       # Linux, macOS
```

## Building, hooks and export

| Symptom | Cause | Fix, and where |
| --- | --- | --- |
| A CI build **fails on a British spelling** | Static checks run `codespell`, which rejects them | Write US English in prose and comments. It rewrites in place, so it will also "correct" a sentence quoting a British spelling as an example. `CLAUDE.md` |
| A hook **"fails" with no message** | `clang-format`, `ruff-format` and `codespell` all rewrite in place | Check `git diff` and commit what the hook did. `CLAUDE.md` |
| **`prek` passes on what is staged and CI still fails** | CI compares against the branch point, so a problem introduced two commits earlier fails the run for whichever commit is on top. Cost a cycle twice | Run the range: `prek run --from-ref origin/master --to-ref HEAD`. `CLAUDE.md` |
| A **bound property change breaks the class reference** and nothing catches it | CI was narrowed to Windows only, dropping the Linux `--doctool` class reference and GDExtension API compatibility checks (unit tests still run — the Windows job runs `--test`) | Run `godot --headless --doctool .` yourself and commit the result. `linux_builds.yml` still carries `workflow_dispatch` for on-demand runs. `docs/VALIDATION.md` |
| An **exported game has none of the fork in it** | The renderer changes are in the binary, not in the project, so stock templates produce a running game with no fork in it | Export against this fork's own `windows-template` CI artifact via **Export -> preset -> Custom Template -> Release**, which sidesteps version matching. `docs/VALIDATION.md` |
| **"Export With Debug", one-click deploy or remote debugging does not work** | There is no `template_debug` build anywhere in the CI matrix | Release exports only; adding the target is a matrix entry plus a CI job. It is also why no shippable configuration has `DEBUG_ENABLED`, which is what turns a push constant mismatch into a hard error — `CLAUDE.md`, and "The frame is black" above |
